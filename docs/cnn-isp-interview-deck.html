02 / Problem + Goal

为什么做这个项目 + 目标边界

把“看图调参”变成可解释工具

传统 ISP 调试重人力、长周期、强经验依赖。这个项目不替代工程师，而是先自动跑完第一轮分析和建议，把人工精力留给最后的微调判断。

流程对比

传统 ISP 调试流程
多设备准备 + 多场景拍摄 不同 sensor / 镜头，人像 / 夜景 / 风景
导出图像数据 + 人工评估图像质量 清晰度 / 噪声 / 曝光
手动调整 ISP 参数 重新编译 / 刷机 / 应用参数
再次拍摄验证 评测是否通过? 评测不通过 -> 全流程重跑
最终目标
输入图像 自动化流程起点
算法自动评估 CNN + CV 指标
自动生成调参建议 自动完成第一轮调参
人工微调 最终结果

从 完全人工调参 走向 算法自动调一轮 + 人工微调。

为什么值得做

  • 高度依赖人工经验，主观性强
  • 需要多设备、多场景反复拍摄
  • 调参周期长，验证成本高
  • 评测不通过 -> 全流程重跑

项目愿景

自动完成 80% 调参工作，人工只负责最终视觉优化和特殊 case 微调。

预期效果

调试时间下降、调参效率提升，结果更稳定且可复现。

本质问题：人眼评估 + 手动调参 = 高成本 + 不稳定 目标：算法先做 80%，人工补最后 20% 定位：自动化第一轮调参辅助系统
03 / Architecture

系统架构与处理流程

输入图像 -> 分析 -> 建议 -> 可视化
Step 1 Decode 接收图像并转成 OpenCV 格式。
Step 2 Semantic Segmentation 识别人、天空、植被、背景。
Step 3 Metric + Structure 计算质量指标，并做 flat/edge/texture 分区。
Step 4 Score + Suggest 归一化打分并生成可回溯建议。
Step 5 Serve + Visualize 通过 API、UI、overlay、JSON 展示结果。

后端模块

segmentation.py 语义分割与 mask 生成
metrics.py 质量指标计算
structure_analysis.py 结构区域划分
analyzer.py 总编排、评分、建议输出

交付接口

  • `POST /analyze` 返回结构化 JSON
  • `GET /` 提供本地调试 UI
  • 结果文件落到 `outputs/` 便于复核
  • 浏览器直接查看图、mask、分数、建议
04 / Semantic Flow

语义分区流程

代码路径：segmentation.py
Step 1 输入 BGR 图像 分析器先完成解码，再把图像送入分割模块。
Step 2 转 RGB + Processor 按 SegFormer 输入格式做预处理。
Step 3 SegFormer 推理 使用 SegFormer 输出 logits。
Step 4 上采样 + argmax 回到原图尺寸，再得到 2D label map。
Step 5 ADE20K 标签映射 `sky` 使用 label 2，聚合成四类 mask。

为什么这样做

  • 先拿到像素级语义，再压缩成答辩真正关心的少数区域
  • background 用非前景区域自动补全
  • 后续区域指标直接复用这些 mask

这一步产出什么

  • 一张和原图同尺寸的语义 label map
  • person / sky / vegetation / background 四类 mask
  • 可直接进入区域评分和 overlay 展示
05 / Structure Flow

结构分区流程

代码路径：structure_analysis.py
Step 1 转灰度图 后续结构特征统一在灰度域计算。
Step 2 Sobel + 局部方差 同时得到 gradient map 和 variance map。
Step 3 阈值划分 mask 高梯度是 edge；低梯度低方差是 flat；其余归 texture。
Step 4 叠加到语义区域 与语义 mask 求交集，用于结构指标和建议生成。

这一步产出什么

  • flat / edge / texture 三类结构 mask
  • gradient map 和 variance map
  • 可与语义区域交叉分析的结构结果

怎么接到评分

  • 原始指标：Laplacian_Clarity、EdgeGrad_mean、sigma_L、sigma_C
  • 先线性归一化到 0-100，再做区域 score
  • 最后按 person 0.5 / sky 0.2 / vegetation 0.2 / global 0.1 汇总
score = 0.35 * clarity + 0.25 * edge + 0.2 * sigma_L + 0.2 * sigma_C

07 / Challenges + Next

难点、取舍与下一步

Q&A

难点 1

区域经常缺失，所以我没有强行置零，而是只对有效区域做重归一化。

难点 2

建议系统如果太复杂就难解释，所以当前优先采用可回溯的规则法。

难点 3

模型下载不稳定，因此测试更聚焦映射逻辑、指标函数和 API 结构。
